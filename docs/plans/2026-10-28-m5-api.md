# Plan: M5 API (FastAPI over Retriever and Answerer)

Status: approved 2026-10-28 (D1 to D6 as recommended); executed with subagent-driven development.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve GetRight over HTTP: a question and a region in, a typed `GeneratedAnswer` out (plain JSON and a stage-streamed version), plus the endpoints the frontend needs for the source panel, the abstention notice and the Help page.

**Architecture:** A thin FastAPI layer in `src/api/`. An `Engine` holds the loaded `Retriever` (bge-m3, reranker, database) and a lazily built `Answerer`, serialises GPU retrieval with a lock, and rebuilds the answerer after an expired OOD session. `create_app(engine)` builds the app, so tests inject an engine with fakes and never load models. Retrieval and generation are not changed: the API calls `Retriever.retrieve(query, region, "hybrid_rerank", gate=True)` then `Answerer.answer(result)`, the same path the gold run used.

**Tech Stack:** Python 3.12, FastAPI and uvicorn (pinned in Task 1), pydantic 2.13.5, httpx 0.28.1 (FastAPI's `TestClient`), pytest. Runs in the `ml` container (GPU for bge-m3 and the reranker).

**Spec:** `CLAUDE.md` (core contribution 1 to 4, architecture step 9, Tech stack "FastAPI, typed Pydantic schemas, streaming", Frontend, Privacy and ethics), `src/generation/schema.py` (the response contract) and `src/retrieval/schema.py`.

## Global Constraints

- The answer and the citations stay separate typed fields; the API returns `GeneratedAnswer` unchanged and never edits answer text or citations (core contribution 1, architecture step 9).
- Traceability, not verification: docstrings and the devlog describe citations as pointing to retrieved provisions, not as proof of legal support (core contribution 2).
- An abstention is a normal HTTP 200 answer with `status: "abstained"`, never an error status (Frontend: "informational notice, not an error").
- One fixed retrieval configuration: `hybrid_rerank`, gate on, from config. No mode, gate, rewrite or threshold parameter in the public API (deterministic pipeline; the rewrite rule is not adopted).
- No server-side conversation storage: the API writes nothing to disk and never logs query or answer text. Logs carry status, region and timings only (Privacy and ethics).
- Bound to `127.0.0.1` only, as the database and `scripts/ask.py` are.
- Secrets stay in `.env`. Error responses never include cookie text or operator instructions; those go to the server log.
- `src/api/` imports no torch at module level; models load only in `Engine.from_config`.
- Docs and devlog: plain English, no em dashes.

## Decisions for the author (D1 to D6)

| # | Decision | Recommendation |
|---|---|---|
| D1 | What "streaming" means. `Answerer` renumbers markers by first use, removes invalid markers and detects `INSUFFICIENT_CONTEXT` anywhere in the reply, all after the full reply. Streaming raw tokens would show text and markers that the final answer then changes, including unchecked citations. | **Stream pipeline stages, not tokens.** Server-sent events: `stage: retrieving`, `retrieval` (gate outcome), `stage: generating`, then one `answer` event with the full `GeneratedAnswer`, or one `error` event. The user sees progress during the 10 to 30 s generator call; every displayed citation is still a checked one. Token streaming goes to future work, with this reason in the report. |
| D2 | Public response shape. | Return `GeneratedAnswer` as is, including `checks`, `generator` and `context_chunk_ids`. It is already the typed contract; a second, trimmed copy would drift. The frontend ignores what it does not show. |
| D3 | Source panel: "full provision text including provisos, fetched live from the corpus". | `GET /api/provisions/{chunk_id}` returns that chunk (content with its provisos, status, deletion and amendment links, page, URL, version) plus `section_chunk_ids`, the ids of every chunk in the same section, so the panel can show the whole section. Source: the chunk records the `Retriever` already holds (the same `chunks.jsonl` the index was built from, same `index_version`). |
| D4 | Two requests at once (double submit, two tabs). bge-m3 and the reranker share one GPU and are not known to be thread-safe. | One uvicorn worker. A lock around `retrieve`; the generator call runs outside the lock (vLLM queues requests itself). |
| D5 | Generator errors. | Expired OOD session: HTTP 503, code `generator_unavailable`; the engine drops its answerer, so the next request re-reads `.env` (no restart, as in `scripts/ask.py`). Other `GeneratorError`: HTTP 502, code `generator_error`. Both with one fixed public message; the detail goes to the server log. |
| D6 | Query limits. | Strip whitespace; empty is 422. Maximum 2,000 characters (the longest gold question is far shorter; it protects the reranker and the prompt budget). Region: `null`, `peninsular`, `sabah` or `sarawak`. |

## API contract

```
GET  /api/health                 {"status": "ok", "index_version": str}
GET  /api/meta                   Meta
POST /api/ask                    AskRequest -> GeneratedAnswer
POST /api/ask/stream             AskRequest -> text/event-stream (events below)
GET  /api/provisions/{chunk_id}  Provision, or 404 ApiError

AskRequest   {query: str (1..2000 after strip), region: Region | null}
Region       "peninsular" | "sabah" | "sarawak"     (keys of config retrieval.regions)
ApiError     {code: str, message: str}
Meta         {statutes_held: list[str], regions: dict[str, list[str]], disclaimer: str,
              index_version: str, prompt_version: str, model: str}
Provision    chunk_id, citation, statute, act_number, part, part_title, section, section_title,
             subsection, chunk_type, jurisdiction, status, deleted_by, content, in_force_notes,
             amended_by, amends, cross_references_internal, cross_references_external,
             source_page, source_page_end, source_url, source_version, section_chunk_ids

SSE events, in order (each "event: <name>\ndata: <json>\n\n"):
  stage      {"stage": "retrieving"}
  retrieval  {"abstained": bool, "abstain_reason": str | null,
              "jurisdictions_found": list[str], "multiple_jurisdictions": bool}
  stage      {"stage": "generating"}          only when not abstained
  answer     GeneratedAnswer                  last event on success
  error      ApiError                         last event on failure (replaces answer)
```

The stream is a POST, so the frontend reads it with `fetch` and a stream reader, not `EventSource`.

## Review Focus

1. Double submit: two requests arrive together. Expected: both succeed; retrieval never runs twice at the same time. Test in Task 2 (`test_retrieve_is_serialised`).
2. The OOD cookie expires while the server is running. Expected: 503 with the fixed message, no cookie text in the body; after the cookie in `.env` is refreshed the next request works without a restart. Tests in Task 2 and Task 3.
3. A question in Malay. Expected: HTTP 200 with `status: "abstained"`, `abstention.reason: "language"`, on both endpoints; not a 4xx. Tests in Task 3 and Task 4.
4. Privacy: the query or answer text ends up in a log line. Expected: never. Test in Task 2 (`test_logs_never_contain_text`).
5. The generator fails after the stream has started (headers already sent). Expected: a final `error` event and a clean end of stream, not a cut connection. Test in Task 4.

### Task 2: Engine

**Files:**
- Create: `src/api/engine.py`, `tests/unit/api_fakes.py`, `tests/unit/test_api_engine.py`

**Interfaces:**
- Consumes: `Retriever.retrieve`, `Retriever.chunks`, `Retriever.statutes_held`, `Retriever.index_version`; `Answerer.answer`; `SessionExpired`, `GeneratorError` from `src.generation.llm`; Task 1 schemas.
- Produces:
  - `Engine(retriever, answerer_factory: Callable[[], Answerer], config: dict)`
  - `Engine.from_config(config_path="config/config.yaml") -> Engine`: `Retriever.from_config()`, one warm-up `retrieve`, factory = `load_dotenv(override=True)` then `Answerer.from_config()`.
  - `Engine.retrieve(query: str, region: str | None) -> RetrievalResult`: under a `threading.Lock`, mode from `config["api"]["retrieval_mode"]`, `gate=True`.
  - `Engine.answer(result: RetrievalResult) -> GeneratedAnswer`: builds the answerer on first use; on `SessionExpired` sets it back to `None` and re-raises.
  - `Engine.ask(query, region) -> GeneratedAnswer`: `answer(retrieve(...))`.
  - `Engine.provision(chunk_id: str) -> Provision | None`: `section_chunk_ids` = chunks with the same `doc_id` and `section`, in document order (a chunk with `section` null gets only itself).
  - `Engine.meta() -> Meta`: `prompt_version` from `src.generation.prompt.PROMPT_VERSION`, `model` from `config["generation"]["model"]`.
  - `api_fakes.py`: `retrieval_result(query, region=None, abstained=False, reason=None) -> RetrievalResult`, `generated(result) -> GeneratedAnswer` (answered with one citation, or abstained to match the result), `FakeRetriever(chunks: dict, delay: float = 0)` recording `calls` and the highest number of concurrent calls in `max_active`, `FakeAnswerer(error: Exception | None = None)`.
- Logging: logger `getright.api`; one line per retrieve (`region`, `abstained`, `ms`) and per answer (`status`, `ms`). No query, answer or chunk text.
