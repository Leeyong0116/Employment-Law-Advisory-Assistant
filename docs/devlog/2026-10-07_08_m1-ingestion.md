## 3. Pipeline architecture
*Report: System Design / Implementation.*

```
PDF ─► extract ─► toc ─► sections ─► schedules ─┐
                                                 ├─► validate ─► chunks.jsonl
A1754 PDF ──────────────► amendments ───────────┘
```

| Stage | Module | Job | Output |
|---|---|---|---|
| 1 | `extract.py` | Clean per-page text; keep printed page number; remove running headers, footnotes, watermarks; repair letter-spaced lines | Pages |
| 2 | `toc.py` | Read the contents pages only into a list of expected sections and schedules | `toc_inventory.jsonl` |
| 3 | `sections.py` | Locate each section in the body, split into subsections and definitions, keep placeholders | Section chunks |
| 4 | `schedules.py` | Chunk schedules; read two-column coverage tables by word coordinates | Schedule chunks |
| 5 | `amendments.py` | Chunk Act A1754; link each amendment to the Cap. 76 chunk it changes | Amendment chunks + links |
| 6 | `validate.py` | Coverage, duplicate ids, editorial text, missing citation fields, broken links | Pass/fail + report |

Run with `python -m src.ingestion.pipeline`. Exits with status 1 if
validation finds any problem.

## 4. Chunking strategy
*Report: Implementation (chunking), Methodology.*

**Rule-based, structure-aware chunking, not fixed-length splitting.** A
fixed-length splitter can cut through a sentence and separate a proviso
from the rule it qualifies. A chunk without its proviso still reads
fluently and cites correctly, but states the law wrongly.

- **Boundary = subsection**, the smallest complete legal rule. An undivided
  section is one chunk.
- **Sections** are located by searching the body for each expected section
  number from the inventory, in order.
- **A new subsection starts** at a line beginning `(n)` only if all three
  hold: it is at the start of a line; it is the next expected number
  (`(2)` after `(1)`, or `(1A)`); the previous line ends a sentence
  (`. ; : — ] )`).
- **Never a boundary:** `(a)`, `(i)` paragraphs; `Provided that` provisos.
- **Definitions** (`“term” means ...`) become one chunk per term. The scope
  sentence ("In this Act, unless the context otherwise requires") is kept
  as metadata because it limits where the definition applies.
- **Deleted and omitted sections** remain as placeholder chunks with
  `status` and `deleted_by`, so "what does section 9 say?" answers
  "deleted by Act 40 of 1966" instead of abstaining.
- **Traceability:** every chunk records `parse_rule` (which rule produced
  it) and `source_page` / `source_page_end`.

## 5. Key design decisions
*Report: Design decisions / Justification.*

| Decision | Rationale |
|---|---|
| Contents-page ranges declared in `config.yaml`, not auto-detected | A wrong automatic guess would silently drop sections. |
| `(Omitted)` sections kept as placeholder chunks, like `(Deleted)` | Coverage stays complete; matches the schema rule that placeholders are never dropped. |
| Act A1754 excluded from the contents inventory | It is an as-passed amending Act with no ARRANGEMENT OF SECTIONS. |
| One chunk per defined term | EA s.2(1) holds dozens of definitions; a single chunk would be too diluted to retrieve. |
| Sarawak Cap. 76 and A1754 kept as separate documents, linked by metadata | A merged text would be a consolidation no authority has published, so users could not verify it. |
| A1754 links go to the narrowest chunk named (definition, then subsection, then section) | Precise links; inserting a new definition supersedes nothing. |
| Cap. 76 chunks changed by A1754 marked `superseded` with `amended_by` links | Retrieval can follow the link to the operative wording. |
| Coverage-schedule exclusions kept with the sub-item they are printed beside | Merging the right-hand column would wrongly apply every exclusion to the whole row. Alignment is recorded as printed, with no legal interpretation. |
| A1754 s.2 ("worker" to "employee" throughout) not linked per chunk | It affects every chunk; applied at prompt time from `jurisdiction_notes`. |
| Footnotes and Sarawak amendment tags moved to metadata | They are editorial annotation, not statute; serving them as law would be a faithfulness failure. |
| Every chunk has the same 40 fields | The vector store (M2) can load a single schema. |

## 6. Implementation challenges and solutions
*Report: Implementation challenges. Each item is a concrete problem met
in the real documents, its cause, the fix, and how the fix was verified.*

| # | Problem found | Cause | Solution | Verified by |
|---|---|---|---|---|
| 1 | Contents pages laid out differently in every statute | Number and title on one line (Sabah) or two (EA, IRA, Sarawak); ranges such as `34-36.`; four placeholder spellings | State-machine parser for the contents pages; ranges expanded; placeholder instrument kept | Counts match an independent raw-text count for all four statutes |
| 2 | Running headers left inside provision text | Sarawak and A1754 use a three-line page header; the third line (`CAP. 76 (1948 ED.)` on 50 pages, `Act A1754` on 44) fell outside the two-line detection window | Third line treated as furniture only if it recurs in that slot across the document and is not numbering such as `(2)` or `12.` | Unit tests; corpus test; manual check that only headers are removed |
| 3 | IRA s.9 not found | Footnote markers before the number: `**9. (1)` | Section-start pattern allows leading asterisks | Corpus coverage test |
| 4 | Sabah ss.75 to 82 not found | Range written `Section 75 — 82` with no full stop, and it also covers lettered `78A` | Range pattern extended; a range absorbs lettered sections whose number falls inside it | Corpus coverage test |
| 5 | Sabah section titles did not match the contents pages | Contents wording outdated (s.102: "Liability of worker for advances" vs body "Limitation on advances to employees") | Fuzzy title match; fallback infers the title from layout and lists it in the report | 8 inferred titles checked by hand against the PDF |
| 6 | False subsection split in Sabah s.130O | PDF line wrap put `(3) of section 18;` at the start of a line | New rule: the previous line must end a sentence before a new subsection can start | Corpus test |
| 7 | Sabah s.34 came out empty | Title inference for deleted s.35 took two lines of s.34's text as a "title" | Inference for untitled placeholders limited to one line, never all-caps headings | Corpus test |
| 8 | IRA s.19 title left on the previous chunk | Title printed one word per line (`compulsory` / `conference` / `for` / `conciliation`) | Title search window widened to ten lines | QA scan of chunk endings |
| 9 | Coverage tables interleaved in plain text | Two-column layout with no ruling lines | Words split into columns at x = 310 pt (measured: right column starts at 316 to 327, left ends by 305) | Every row of all three tables checked by hand |
| 10 | Sabah exclusion attached to the wrong row | Right-hand block printed 2.6 pt above its row (y 283.8 vs 286.4) | Block assigned by its top line plus a 6 pt tolerance | Manual check of all rows |
| 11 | Sarawak Schedule swallowed the amendment list | `LIST  OF  AMENDMENTS` printed with double spaces | Whitespace-tolerant end-matter pattern; title block stepped over by line shape | Unit test reproducing the Sarawak layout |
| 12 | Duplicate A1754 chunk ids | `(i)` matched both as a letter paragraph and a roman numeral | Paragraph markers must follow their sequence (a, b, c / i, ii, iii) | Unit and corpus tests |
| 13 | A1754 over-linking | "By inserting after the definition of X" linked every s.2 chunk | Insertions of new definitions supersede nothing | Corpus test |
| 14 | Deleted Cap. 76 definitions not marked | Short instruction "(ix) by deleting the definition of “family”" merged into the next part | Only true lead-ins (ending in a dash or colon) are merged | Corpus test |

**Observation for the report:** several fixes are trade-offs between two
failure modes. Rule 6 (sentence end before a new subsection) prevents
false splits, but causes a missed split where the source itself omits a
full stop (see Limitations, item 1).

## 10. Design discussions (no code yet)
*Report: Design (interface, privacy, observability).*

- **Pipeline trace for troubleshooting.** Decided against relying on the
  model's own "thinking" text: it is not reliable evidence and does not
  show retrieval failures. Instead, a deterministic per-query trace
  (query, language, filters, dense and BM25 candidates with scores,
  reranker scores, abstention decision against threshold, prompt, raw
  output, citation mapping). On for development and evaluation, off by
  default in the live app, to respect the "no server-side conversation
  storage" rule. The ingestion half is in place via `parse_rule` and
  source pages.
- **Chat history.** No server database: it would require user identity and
  bring PDPA 2010 obligations, and adds nothing to the evaluated
  contribution. History stays in browser `localStorage`, display only
  (follow-ups do not use earlier messages, keeping retrieval deterministic
  and RAGAS comparisons valid). Known drawbacks: one device only, lost on
  clearing browser data, readable on shared computers, citations can go
  stale after re-ingestion. Mitigations: clear-history button, short
  notice, store corpus version and date per entry.
- **Source PDFs published.** Committed to the public repository so a fresh
  clone can run the corpus tests; they are official published statute text.

## 12. Follow-up fixes (8 October, later)
*Report: Implementation challenges; Testing (how errors were found).*

Both known errors from Section 9 were fixed after the automated quality
scan, and the pipeline was re-run. Figures in Sections 7 and 8 are from
before these fixes; the current figures are below.

**Fix 1: subsections whose previous subsection has no full stop.**

| | |
|---|---|
| Problem | Sabah s.121I(3) and (4) were one chunk. The source omits the full stop after (3)(b) "of good quality", and the sentence-end rule (Section 6, item 6) blocked the split. |
| Fix | A next-expected marker also opens a subsection when the text after it starts with a capital letter ("(4) Any employer"). A wrapped reference continues in lower case ("(3) of section 18"), so the s.130O case stays correct. A bare marker looks at the next line. |
| Side effect found | The same fix split **EA s.60I(1A), (1B) and (1C)**, which had also been merged: the formula line "26" has no full stop either. The earlier automated scan had **not** detected this, because the joined text hid the marker. This is concrete evidence that automated scans miss error types, and a reason for the manual audit. |
| Verified by | Three new unit tests; chunk-id diff before and after the re-run showed exactly three new chunks (`EA1955_s60I_1B`, `EA1955_s60I_1C`, `SBH67_s121I_4`) and none removed; each checked against the PDF. |

**Fix 2: fractions in formulas.**

| | |
|---|---|
| Problem | A fraction bar is a drawn line in the PDF, not a character, so the text layer lost the division: EA s.60I(1A) read `monthly rate of pay . 26` instead of monthly rate of pay divided by 26. |
| Fix | `extract.py` finds short horizontal drawn lines, takes the text within 16 pt above as the numerator and below as the denominator, and rewrites them as `monthly rate of pay / 26`. Longer sides are bracketed. Lines that come out between the two sides (the "X" and second factor in EA s.18A) are placed after the fraction. A short rule above a `*NOTE` is recognised as a footnote separator and left alone. |
| Formulas fixed | EA s.18A, EA s.60I(1A) and (1B), Sabah s.2(3)(a) and (b), A1754 s.39 (new Cap. 76 s.109). |
| Example | EA s.18A now reads: `(Monthly wages) / (Number of days of the particular wage period) X Number of days eligible in the wage period.` |
| Verified by | Six unit tests (one per layout variant met: stray full stop, stray semicolon, two-line denominator, product printed in between, factor order reversed, footnote rule); two corpus tests. |

**Current figures (after both fixes):** 1,852 chunks (EA 370, IRA 273,
Sabah 627, Sarawak 435, A1754 147); 1,486 provision, 202 definition, 147
amendment, 11 schedule_row, 6 schedule; validation clean; **184 tests
