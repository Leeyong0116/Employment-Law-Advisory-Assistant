## 1. Summary

GetRight now runs over HTTP. A thin FastAPI layer (`src/api/`) takes a
question and a region and returns the same typed `GeneratedAnswer` that M4
produces, as plain JSON or as a stream of pipeline stages. It also serves the
full provision text for the source panel and the list of statutes held for
the abstention notice and the Help page. Retrieval and generation were not
changed.

- 37 new tests (schema 8, engine 10, app 12, stream 7); 474 in total, all
  passing.
- Live smoke run through HTTP: 7/7 checks (Section 6).
- The real server answered `/api/meta` from the Windows host with seven
  statutes and three regions.

## 2. API contract

```
GET  /api/health                 {"status": "ok", "index_version": str}
GET  /api/meta                   statutes_held, regions, disclaimer, index_version, prompt_version, model
POST /api/ask                    {query, region} -> GeneratedAnswer
POST /api/ask/stream             {query, region} -> text/event-stream
GET  /api/provisions/{chunk_id}  full chunk + section_chunk_ids, or 404
```

`region` is `null`, `peninsular`, `sabah` or `sarawak`. The query is
stripped; empty or over 2,000 characters is a 422.

Stream events, in order: `stage {retrieving}`, `retrieval` (gate outcome),
`stage {generating}` (only when the gate passed), then one `answer`
(`GeneratedAnswer`) or one `error` (`{code, message}`).

## 3. Decisions (D1 to D6, all taken as recommended in the plan)

| # | Decision | Why |
|---|---|---|
| D1 | Stream pipeline stages, not tokens. | `Answerer` renumbers markers, removes invalid ones and detects `INSUFFICIENT_CONTEXT` only after the full reply. Streamed tokens would show text and markers the final answer then changes, including unchecked citations. The user still sees progress during the 10 s generator call. Token streaming is future work, for this reason. |
| D2 | Return `GeneratedAnswer` unchanged. | It is already the typed contract; answer and citations stay separate fields, and the API never edits either (core contribution 1). A second trimmed copy would drift. |
| D3 | `GET /api/provisions/{chunk_id}` with `section_chunk_ids`. | The source panel shows the full provision, provisos included, from the same chunk records the index was built from. Sibling ids let the panel show the whole section. |
| D4 | One worker; a lock around retrieval; generation outside the lock. | bge-m3 and the reranker share one 8 GB GPU and are not known to be thread-safe. vLLM queues requests itself. |
| D5 | Expired OOD session: 503 `generator_unavailable`; other generator errors: 502 `generator_error`. | One fixed public message each. The real detail (which names the cookie and `.env`) goes to the server log only. The engine drops its answerer after an expired session, so a refreshed cookie works on the next request without a restart. |
| D6 | Query 1 to 2,000 characters after stripping; region from a fixed list. | Protects the reranker and the prompt budget. |

Also fixed by design:
- The retrieval configuration is not a request parameter. The API always
  uses `hybrid_rerank` with the gate on (from `config.yaml`, `api:`), so what
  users see is what the evaluation measured. The query rewrite rule is not
  adopted, so it is not in the API.
- An abstention is HTTP 200 with `status: "abstained"`, not an error (the
  frontend shows it as an informational notice).
- Citations point to the retrieved provision a statement came from. This is
  traceability, not proof that the provision legally supports the statement
  (core contribution 2).
- Privacy: the API writes nothing to disk and never logs query, answer or
  chunk text. Log lines carry region, status, abstain reason and timings
  only. A test asserts this (`test_logs_never_contain_text`).
- CORS allows only the Vite dev server (`http://localhost:5173`), GET and
  POST. The server binds to `127.0.0.1` through the Docker port mapping.

## 4. Code

| File | Job |
|---|---|
| `src/api/schema.py` | `AskRequest`, `Region`, `ApiError`, `Meta`, `Provision` (no parser internals such as `parse_rule`) |
| `src/api/engine.py` | `Engine`: loaded `Retriever`, answerer built on first use, retrieval lock, section index for provisions, privacy-safe logging |
| `src/api/app.py` | `create_app(engine)`, `build()` for uvicorn, generator error mapping, CORS |
| `src/api/stream.py` | `ask_events`: server-sent stage events; a failure after headers are sent ends the stream with an `error` event |
| `src/api/smoke.py` | Live checks through `TestClient` on the real engine |
| `tests/unit/api_fakes.py` | Fake retriever (counts concurrent calls) and answerer; no models in unit tests |

`create_app` takes the engine as an argument, so every unit test runs on
fakes and loads no model.

Run the server:

```
docker compose run --rm -p 127.0.0.1:8000:8000 ml uvicorn src.api.app:build --factory --host 0.0.0.0 --port 8000 --workers 1
```

## 7. Operations note: refreshing the OOD cookie

Recorded because it cost time in this session.
1. Log in to Open OnDemand, open the running Jupyter session (vLLM is
   started from its terminal; `history | grep vllm` shows the command).
2. Browser F12, Network, Doc filter, reload, first request, Request Headers,
   copy the whole `Cookie:` value (it contains `mod_auth_openidc_session`).
3. Replace only the `OOD_COOKIE_SECRET=` line in `.env`, keep
   `GENERATOR_BASE_URL=`, save. Check with `python -m src.generation.check`.

A paste in this session overwrote the `GENERATOR_BASE_URL` line; it was
restored from the earlier value (same GPU node).

## 8. Limitations

- Single user by design (one worker, one lock). Fine for a local demo, not
  for deployment (deployment is future work).
- No token streaming (D1).
- The generator depends on an OOD browser cookie that expires; a hosted API
  is a config switch (`api_key_env`), not a rewrite.

## 10. Environment recovery (28 October)

Before M5 work started, the Docker images and containers were gone (both
`pgvector/pgvector:pg16` and `getright-ml`). The named volumes survived:
`getright-pgdata` (the index) and `getright-hf-cache` (model weights).

- `docker compose up -d` pulled the database image and reattached the
  volume. The `chunks` table still held all 1,897 rows; no re-embedding was
  needed.
- `docker compose --profile ml build ml` rebuilt the ML image from
  `requirements.txt`.
- `python -m src.indexing.smoke`: 7/7 on index `459843bf28ba`, the same index
  as before.

Lesson: only the volumes hold state. `docker compose down -v`,
`docker system prune --volumes` or Docker Desktop's "purge data" delete the
index. If that happens, `python -m src.indexing.build` rebuilds it from
`data/processed/chunks.jsonl`, which is in the repository.
